# BAO Toolkit v0.6.1: Doctor reliability

Status: in development. This brief defines the repair scope; it is not a publication record.

## Scope and compatibility

- Stop treating locally implemented attribution helpers as proof of protection,
  including suffix aliases and local namespace objects.
- Report empty Doctor scopes as unmeasured in CLI and Action summaries. Preserve
  the numeric JSON and Action `coverage` output for compatibility; consumers must
  check the total path count before interpreting that value.
- Keep the Action's existing empty-scope failure policy and scanner exit semantics.
- Update the package inventory and architecture documentation for the shipped v0.6.

Patch Changesets cover scanner, CLI, and GitHub Action. Core, B20, adapters, public
schemas, rule IDs, Action inputs, npm scope, and the `bao` command retain their
contracts. Package versions and changelogs belong in a separate version change.

## Verification gates

- Regression tests for local helpers, aliases, namespace objects, lexical
  shadowing, trusted imports, literal suffixes, and cross-file configuration.
- CLI and packed Action checks for false protection and empty scopes.
- Formatting of changed files, lint, typecheck, the complete test suite, build,
  size budgets, and all nine packages in a clean consumer.

This patch does not claim runtime verification or external adoption. External
integration pilots and grant evidence remain separate follow-up work.

## Local verification, 2026-10-05

- Lint, typecheck, and 400 tests across 30 test files passed.
- Production builds and package size budgets passed.
- The production dependency audit reported no known vulnerabilities.
- All nine packed packages passed the clean-consumer smoke suite, including
  Doctor regressions, Action summaries, SARIF, and both `fail-on-missing` modes.
- Changesets projects patch updates for scanner, CLI, and GitHub Action only.
