# Base Attribution OS v0.6.0 release proposal

Status: proposed, not released. The owner requested B20 expansion on 2026-09-29.
P0/P1 covers protocol grounding and token inspection in draft PR #21. The local
P2 increment adds bounded receipt-aware replay and attribution policy. P3/P4 add
the viem client example, static report pages, exact artifact downloads, and a
technical pilot kit. Code-candidate checks and UI verification are recorded in
`docs/b20/implementation-status.md`; live qualification remains incomplete.

## Package intentions

- New `@base-attribution-os/b20`: currently 0.1.0, not published; the replay
  Changeset projects 0.2.0 if both increments ship together.
- CLI: minor change from 0.4.0 to proposed 0.5.0 for additive B20 commands.
- Existing core, adapters, scanner, wallet, and Action public contracts stay unchanged.

Changesets requests B20 and CLI minor increments and an Action patch. The Action
also pins its HTTP client's undici dependency to 6.28.1 to fix the production
audit finding. No Action inputs change. Review the first B20 release version
before a separate version PR.

## Current boundary

Token inspection, bounded transaction/receipt replay, factory creation evidence,
direct-call attribution coverage, strict attribution policy, offline validation,
explicit historical RPC rechecking, and deterministic synthetic fixtures.
The existing docs app serves `/b20`, `/b20/guide`, and statically registered
report/export/capture routes. It performs artifact validation without runtime RPC.
No RPC endpoint is selected by default. Unknown epochs are not labeled qualified.

The CLI gains viem through the new package. Existing core/adapters do not inherit
that dependency. Replay's ABI decoders, evidence parsers, and collector increase
B20's combined ESM/CJS budget from 64 to 176 KiB, including its RPC subdirectory.
The CLI budget increases from 48 to 56 KiB for replay commands and bounded
artifact IO. viem remains external.

## Gates for the full Foundation release

Review the candidate checks and package intentions before describing Foundation
as released. The broken/fixed example uses synthetic receipts; native execution
and an external pilot remain untested. Keep code completion, live qualification,
and external validation separate.

Publishing packages, tagging, production deployment, and outreach require a
separate release decision. This proposal does not claim those actions occurred.
