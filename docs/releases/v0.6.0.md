# Base Attribution OS v0.6.0 release proposal

Status: proposed, not released. The owner requested B20 expansion on 2026-09-29.
The first implementation slice is P0/P1 from the supplied handoff: protocol
grounding and token inspection. The full B20 Foundation remains in progress.

## Package intentions

- New `@base-attribution-os/b20`: initial version 0.1.0, not published.
- CLI: minor change from 0.4.0 to proposed 0.5.0 for additive B20 commands.
- Existing core, adapters, scanner, wallet, and Action public contracts stay unchanged.

The new package already carries its intended initial version; the Changeset
requests the CLI minor increment. `pnpm exec changeset status` also projects an
Action patch because it depends on the CLI. No Action inputs or behavior change.
Review that dependency bump before a separate version PR.

## Current boundary

Token inspection, strict inspection-artifact parsing, offline validation,
explicit historical RPC rechecking, and deterministic synthetic fixtures.
No RPC endpoint is selected by default. Unknown epochs are not labeled qualified.

The CLI gains viem through the new package. Existing core/adapters do not inherit
that dependency. B20 owns a 64 KiB combined ESM/CJS bundle budget including its
RPC subdirectory. The CLI remains within its existing 48 KiB budget, including
command wiring, bounded artifact IO, formatting, and configuration validation;
viem remains external.

## Gates for the full Foundation release

Token inspection alone does not complete B20 Foundation. Before describing the
full Foundation as shipped, implement and verify receipt-aware bounded replay,
attribution coverage, strict attribution policy, factory creation evidence,
the broken/fixed transaction example, public report pages, and the pilot kit.
Keep code completion, live qualification, and external validation separate.

Publishing packages, tagging, production deployment, and outreach require a
separate release decision. This proposal does not claim those actions occurred.
