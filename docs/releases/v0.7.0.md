## Scope

- A runnable viem starter with broken and fixed application paths and an offline
  transport. Doctor findings and the actual outgoing calldata must agree.
- `bao init` previews the exact scan scope and proposed files, explains findings,
  and optionally creates a pinned GitHub workflow without replacing one.
- A version-pinned compatibility corpus with positive and negative controls,
  including official ox helpers and wallet capability failures.
- A local pilot summary joins source audit metadata with optional existing Proof
  Sets. It keeps source and transaction coverage separate and identifies evidence
  supplied by the caller.
- A public integration route explains reproduction and how to request a pilot.

## Package and compatibility boundary

The CLI received a minor Changeset for the new initialization options and pilot
summary command. Core received a patch for round-tripping unverified Proof Sets
through JSON when an optional explorer URL is absent. Existing Doctor JSON, empty-scope exit behavior, Proof Set v1,
SDK APIs, package scope, and Action inputs remain compatible. The separate
version PR applied the versions above. No new hosted service or default telemetry.

Changesets also applied dependency patch releases for the other seven packages.
Their repository metadata uses `horn111/bao-toolkit` for npm provenance. The CLI
JavaScript budget grows from 56 to 76 KiB for init previews/workflow templates and
the pilot report; browser SDK budgets remain unchanged.

PostCSS uses `source-map-js` 1.2.2 through a scoped override to address
[GHSA-68fv-2mgg-jv7q](https://github.com/advisories/GHSA-68fv-2mgg-jv7q),
reported by the publication-day dependency audit.

## Acceptance gates

- Broken starter: strict Doctor fails and captured calldata lacks the code.
- Fixed starter: strict Doctor passes and captured calldata contains the code.
- Initialization preview writes nothing; generated scope matches the audit;
  existing workflows are preserved, including when `--force` is supplied.
- Pilot summaries record commit and dirty state, code, scope, versions, findings,
  and optional transaction evidence without claiming independently verified use.
- Compatibility checks name exact dependency versions and distinguish static
  detection from runtime checks. Node 20, 22, and 24 run the offline integration
  checks in CI; local results alone do not count as completed matrix results.
- Lint, typecheck, tests, builds, size, and clean-consumer package verification pass.

External pilot acceptance remains a separate follow-up: another team reproduces
a useful result, accepts a fix, and keeps the CI check. Shipping this train does
not establish external adoption or grant eligibility.
